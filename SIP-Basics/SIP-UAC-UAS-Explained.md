# SIP UAC vs UAS — Understanding the Basics

Understanding the basics of SIP (Session Initiation Protocol) is not difficult at all once you grasp its core concept.

The line "An endpoint typically functions as both UAC and UAS" often confuses people initially because we usually think of the client-server model as completely separate (like your browser is always the client and Google's server is always the server).

But in SIP, the story is a little different. Let's understand this in simple terms with a practical IT diagrammatic example.

## Core Concepts: UAC vs UAS

First, let's simplify these two terms:

- **UAC (User Agent Client):** This is the device or software that sends a request (like initiating a call).
- **UAS (User Agent Server):** This is the device or software that receives a request and sends back a response (like accepting a call or ringing).

## Why Does That Line Create Confusion?

Your SIP phone (whether it's a hardware desk phone or a Softphone on a laptop) is an **Endpoint**. This endpoint can alternately do the job of both a UAC and a UAS.

- When you call someone, your phone generates a request → It becomes a **UAC**.
- When someone calls you, your phone receives a request → It becomes a **UAS**.

## IT Example Diagram (The Call Flow)

To understand this, look at the sequence below. Assume there are two users: Phone A and Phone B, connected to each other through a SIP Server (Asterisk/PBX).

```
  [ Phone A ]                  [ SIP Server ]                  [ Phone B ]
  (Endpoint)                     (IP-PBX)                       (Endpoint)
      |                             |                               |
      |--- 1. INVITE -------------->|                               |  <- Phone A acts as UAC
      |    (Bro, connect the call)  |--- 2. INVITE ---------------->|  
      |                             |    (Bro, you have a call)     |
      |                             |                               |
      |                             |<-- 3. 180 Ringing ------------|  <- Phone B acts as UAS
      |<-- 4. 180 Ringing ----------|    (Phone is ringing)         |
      |    (Phone is ringing)       |                               |
      |                             |                               |
      |                             |<-- 5. 200 OK -----------------|  <- Phone B sends Success
      |<-- 6. 200 OK ---------------|    (Call answered!)           |
      |    (Call answered!)         |                               |
      |                             |                               |
      |========== 7. RTP MEDIA STREAM (AUDIO TALK) =================|  <- Real-time voice traffic
      |                             |                               |
```

### The Role of UAC and UAS in This Diagram

- **Phone A (UAC Role):** When Phone A started the call, it sent an INVITE request. At this moment, Phone A is a Client (UAC).
- **Phone B (UAS Role):** Phone B received that INVITE request and, in return, sent the 180 Ringing and 200 OK responses. At this moment, Phone B is a Server (UAS).

## Role Reversal (When the Story Flips)

Now imagine the conversation is over and Phone B hangs up the call. In SIP, a BYE request is sent to end the call.

```
  [ Phone A ]                  [ SIP Server ]                  [ Phone B ]
  (Endpoint)                     (IP-PBX)                       (Endpoint)
      |                             |                               |
      |<-- 2. BYE ------------------|<-- 1. BYE --------------------|  <- NOW Phone B acts as UAC!
      |    (End the call)           |    (I am hanging up)          |
      |                             |                               |
      |--- 3. 200 OK -------------->|                               |  <- NOW Phone A acts as UAS!
      |    (Done, call ended)       |--- 4. 200 OK ---------------->|
```

- **Phone B now became UAC:** Because this time, the request (BYE) was generated by Phone B.
- **Phone A now became UAS:** Because it received the request and sent back the response (200 OK).

## 💡 Takeaway

In SIP, every smart device (IP Phone, WebRTC client, Softphone) is a **User Agent (UA)**. When it sends a request, it's called a **UAC**, and when it listens to a request, it's called a **UAS**. A single endpoint plays both roles during the course of a single call.
